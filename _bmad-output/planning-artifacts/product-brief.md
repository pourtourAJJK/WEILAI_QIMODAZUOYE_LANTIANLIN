# 产品简报：影羽·YINGYU STUDIO

## 一句话定位

**可视化个人简历 + 可视化商业展示窗口** —— 面向摄影与视频创作者的作品展示网站，将传统文字简历转化为有真实作品支撑的项目案例集合，同时面向潜在客户提供从作品浏览到合作提交的完整路径。

## 解决什么问题（四个痛点）

1. **作品呈现分散** —— 摄影、视频类创作者的作品散落在短视频平台、社交媒体和网盘，分类不统一、项目介绍不完整、个人职责不明确，企业/客户难以快速判断实际能力
2. **咨询承接低效** —— 普通留言框只记录一段文字，管理员需要再次询问服务类型、联系方式和预计时间；没有处理状态管理，已联系与未答复的记录难以区分
3. **数据口径模糊** —— "页面被打开" ≠ "视频被播放" ≠ "完播"，如果混为一谈，统计看板有数字但无法解释作品表现
4. **维护成本高** —— 单人管理的作品网站若额外部署独立业务服务器，环境配置和运维工作与业务规模不匹配

## 目标用户与使用场景

| 角色 | 场景 | 目标 |
|------|------|------|
| **潜在雇主 / 客户** | 通过搜索引擎或社交链接进入，快速判断创作者风格与能力 | 在 30 秒内知道"这个人拍得好不好"，在 3 分钟内找到感兴趣的作品并留下合作意向 |
| **创作者本人（管理员）** | 登录后台维护作品、处理客户记录、查看观看数据 | 10 分钟内完成一部作品的上传发布；5 分钟内处理一条客户咨询 |

## 核心价值主张

- **从"看简历"变成"看作品"** —— 访客先看代表作品（33 秒 Showreel），再了解个人介绍和项目经历，作品优先于文字
- **从"孤立展示"变成"完整链路"** —— 作品展示 → 合作意向提交 → 客户跟进 → 数据统计，三者共用同一数据链路
- **从"界面约束"变成"云端规则"** —— 业务规则（幂等、版本校验、工作日截止、完播判定）下沉到后端，不靠前端 UI 做安全边界

## 技术选型（已确认）

| 层 | 技术 | 说明 |
|----|------|------|
| 前端 | Vue 3 + Vite + Vue Router + ECharts | 与开题报告一致；前后台分离，分别构建 |
| 后端 | Django REST Framework | 替代开题报告原 CloudBase RPC 架构；所有业务规则通过 DRF 视图 + Service 层实现 |
| 数据库 | SQLite（开发）/ PostgreSQL（生产） | 13 张业务表按开题报告的数据模型迁移 |
| 文件存储 | 本地 media/（开发）/ 对象存储（生产） | 开题报告用腾讯云 COS，开发阶段简化为 Django media |

> **架构调整说明**：开题报告后端采用 CloudBase PostgreSQL + RPC 函数（无独立业务服务器，业务逻辑全在数据库层）。本次实现改用 Django REST Framework，在保持全部业务规则的前提下，将 RPC 函数迁移为 DRF 视图 + Service 层 + 数据库模型约束。调整原因：课程要求使用 Django，更符合标准 Web 开发范式。

## 范围边界（本期）

### ✅ 已纳入

**前台（5 路由）**
- 首页品牌展示 + 约 33 秒个人 Showreel
- 作品目录（瀑布流网格 + 两级分类筛选）
- 作品详情弹窗（封面轮播 + 视频播放 + 项目档案）
- 合作需求提交（姓名/邮箱/合作类型/周期/描述 + 幂等 + 限流）
- 联系方式提交 + 商业空间介绍页

**后台（6 模块）**
- 管理员登录（Django Auth + 图片验证码）
- 概览统计（作品数/咨询数/趋势摘要）
- 作品管理 + 素材上传 + 乐观锁版本校验
- 客户需求管理 + 状态流转 + 状态历史 + CSV 导出
- 站点内容维护（品牌/介绍/联系方式/Showreel 配置）
- 工作日历配置 + 观看统计看板（PV/UV/节点到达率/完播率）+ 作品排行榜

**核心业务规则（从开题报告迁移）**
- 表单幂等（requestId 去重）+ 频率限制
- 作品乐观锁版本控制（保存时携带版本号，冲突拒绝覆盖）
- 工作日截止时间计算（跳过休息日，策略版本冻结）
- 视频自然播放区间采集 + 完播判定（结束事件 + 覆盖 ≥ 98% + 尾部自然到达）
- 作品软删除（前台隐藏，后台保留）
- 客户状态历史（状态变更与历史写入在同一事务）
- 本地草稿暂存（作品编辑器 + 工作日历日程弹窗）

### ❌ 不纳入（本期范围外）

- 多角色审批体系（本期仅一名管理员）
- 付费观看 / 访客会员体系
- 跨设备实时推送（不同设备依赖手动刷新）
- 高并发压力测试（以功能可用性和规则正确性为主）
- 正式域名绑定（开发阶段用 localhost）
- 视频加密防盗链（开发阶段简化）

## 约束与依赖

- **单人独立开发** —— 所有功能由一人完成，架构复杂度与业务规模匹配
- **Windows 开发环境** —— Python 3.11 + Node v24，命令行使用 PowerShell 5（不支持 `&&`、`mkdir -p` 等 Unix 语法）
- **无真实商业素材** —— 作品素材以测试和演示内容为主
- **无 CloudBase 后端依赖** —— 开题报告的 RPC 函数全部重写为 DRF Service 层
